WHAT WAS BUILT
--------------------------------------------------------------------------------

1. LLM Abstraction Layer (app/llm/)
   - LLMClient: structural Protocol (runtime_checkable) — any object
     implementing get_structured_completion satisfies it
   - GoogleLLMClient: real provider backed by langchain-google-genai;
     uses with_structured_output for Pydantic-typed JSON responses;
     temperature=0 for deterministic extraction
   - FakeLLMClient: test double — configurable response or error; tracks
     call_count; never makes network calls
   - get_llm_client(settings): factory — currently routes "google" only;
     raises ValueError for unknown providers; designed for future extension

2. LLM-Facing Schema (app/llm/schemas.py)
   - ExtractedTermSchema: what the LLM returns (name, value,
     normalized_value, category, confidence, evidence_ids, notes)
   - ExtractionOutput: top-level structured response (list[ExtractedTermSchema])
   - Intentionally SEPARATE from DealTerm — the LLM schema is a
     prompt/response contract; DealTerm is the application domain model

3. Extraction Prompts (app/agents/extraction/prompts.py)
   - SYSTEM_PROMPT: grounds the agent in its role as a pure extractor
     - Explicit prohibition on compliance analysis
     - Explicit prohibition on risk analysis
     - Explicit instruction to preserve qualifiers exactly
     - Explicit instruction to represent conflicting/ambiguous values
     - Explicit ban on inventing evidence IDs
   - serialize_evidence(): converts EvidenceSnippet objects into a
     structured text block; format: [EV-NNN] Page N | Section: ...

4. Term Extraction Agent (app/agents/extraction/term_extraction.py)
   - TermExtractionAgent.extract(evidence_registry) → (terms, rejections)
   - Guards:
     - Empty registry → ([], []) without calling LLM
     - Hallucinated / absent EV IDs → term REJECTED, reason recorded
     - Rejection reasons are explicit, non-empty human-readable strings
   - Merging:
     - Same name + same value → one term with all EV IDs combined
     - Same name + different values → both terms, both AMBIGUOUS
   - ID assignment: TERM-001, TERM-002, ... (sequential, deterministic)
   - LLM client is INJECTED — agent is fully testable with FakeLLMClient

5. LangGraph Node (app/orchestration/graph.py)
   - make_extract_terms_node(llm_client): factory — captures client via
     closure; node has plain (state) -> dict signature for LangGraph
   - build_graph(llm_client=None): module-level graph safe for all existing
     tests (llm_client=None → graceful skip + TERM_EXTRACTION_FAILED)
   - Graph: START → initialize_run → ingest_document → extract_terms → END
   - Audit events:
     - TERM_EXTRACTION_STARTED
     - GENERIC [WARNING] for each rejected candidate (hallucinated EV)
     - TERM_EXTRACTION_COMPLETED (with term_count, rejection_count)
     - TERM_EXTRACTION_FAILED for LLM/config errors

6. Audit Events (app/models/audit.py)
   - Added: TERM_EXTRACTION_STARTED, TERM_EXTRACTION_COMPLETED,
            TERM_EXTRACTION_FAILED

--------------------------------------------------------------------------------
DESIGN PRINCIPLES PRESERVED
--------------------------------------------------------------------------------

1. LLM reasons over EvidenceRegistry, NOT the PDF
2. EvidenceSnippet IDs are immutable; hallucinated IDs are rejected
3. LLMClient is injected — agents are independently testable
4. One LLM call per document (no RAG, no per-snippet calls)
5. Exactly 4 agents: orchestrator, term_extraction, compliance, risk_summary
6. Confidence stored as signal only — no threshold-based auto-rejection
7. Conflicting evidence preserved (AMBIGUOUS), never silently resolved
8. Prompt explicitly forbids compliance and risk reasoning
9. build_graph(llm_client=None) preserves all 258 existing tests
